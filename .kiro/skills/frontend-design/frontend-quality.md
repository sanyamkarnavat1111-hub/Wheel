# Frontend Quality Standard

You are not merely implementing UI.
You are acting as a senior product designer, design engineer,
UX engineer and frontend architect.

Every frontend change must satisfy this document.

## PRIMARY OBJECTIVE

The website must look like it was designed by an experienced
product design studio, not generated by an AI coding assistant,
intern or template generator.

Prioritize:

1. Visual hierarchy
2. Typography
3. Spacing
4. Composition
5. Brand consistency
6. Responsiveness
7. Accessibility
8. Performance
9. Interaction quality
10. Maintainability

Never optimize for speed of implementation at the expense
of visual quality.

---

# DESIGN DIRECTION

Before implementing a major page:

1. Understand the product.
2. Identify the target audience.
3. Identify the primary conversion goal.
4. Establish a visual direction.
5. Establish typography.
6. Establish color system.
7. Establish spacing system.
8. Establish component language.
9. Only then implement.

Do NOT immediately start writing JSX/CSS.

---

# NEVER PRODUCE

Avoid:

- Generic SaaS layouts
- Generic AI landing pages
- Purple gradient backgrounds unless explicitly requested
- Random gradients
- Excessive glassmorphism
- Excessive rounded cards
- Excessive shadows
- Random floating blobs
- Generic hero sections
- Huge meaningless headings
- Excessive animations
- Decorative elements without purpose
- Stock-looking illustrations
- Emoji used as UI decoration
- Repeated card grids when another composition is better
- Inconsistent border radii
- Inconsistent spacing
- Arbitrary font sizes
- Arbitrary colors
- Placeholder-looking content

Never use visual effects merely because they are easy to generate.

---

# TYPOGRAPHY

Typography must have a deliberate hierarchy.

Define:

- Display
- H1
- H2
- H3
- Body
- Small
- Caption

Use a consistent type scale.

Never randomly assign font sizes to individual elements.

Use high-quality typography with intentional font pairing.

---

# SPACING

Use a consistent spacing system.

Prefer tokens such as:

--space-1
--space-2
--space-3
--space-4
--space-5
--space-6
--space-8
--space-10
--space-12
--space-16
--space-20
--space-24

Do not invent arbitrary spacing values unless there is a
strong design reason.

---

# COLORS

Define a semantic color system.

Examples:

--background
--foreground
--muted
--surface
--surface-elevated
--border
--primary
--primary-hover
--secondary
--success
--warning
--error

Do not scatter hex values throughout components.

---

# COMPONENTS

Prefer reusable components.

Before creating a new component ask:

"Does this pattern already exist?"

If yes, reuse it.

If a pattern appears three or more times,
extract a reusable component.

Components must have consistent:

- spacing
- typography
- radius
- borders
- shadows
- hover states
- focus states
- disabled states

---

# RESPONSIVE DESIGN

Every page MUST work at:

320px
375px
390px
430px
768px
1024px
1280px
1440px
1920px

Do not simply shrink desktop.

Design mobile intentionally.

Check:

- navigation
- hero
- typography
- buttons
- grids
- cards
- images
- forms
- tables
- horizontal overflow
- spacing
- footer

There must be no accidental horizontal scrolling.

---

# ACCESSIBILITY

Follow WCAG 2.2 AA principles.

Every interactive element must:

- be keyboard accessible
- have visible focus
- have an accessible name
- have appropriate semantic HTML
- have sufficient color contrast
- have appropriate touch target size

Images require meaningful alt text where appropriate.

Decorative images must not create unnecessary screen-reader noise.

Do not use color as the only means of communicating information.

Respect reduced-motion preferences.

---

# INTERACTION

Interactive elements require:

- hover
- focus
- active
- disabled
- loading states where applicable

Animations must communicate hierarchy or interaction.

Avoid animation for decoration alone.

Respect:

prefers-reduced-motion

---

# PERFORMANCE

Avoid unnecessary:

- JavaScript
- client-side rendering
- large dependencies
- image payloads
- animation libraries
- layout shifts

Prefer CSS animations when sufficient.

Optimize images.

Lazy-load below-the-fold media.

Avoid unnecessary re-renders.

---

# SEO

Pages should include:

- meaningful title
- meta description
- canonical URL where appropriate
- semantic heading hierarchy
- Open Graph metadata
- appropriate structured data where useful

Only one primary H1 per page.

---

# QUALITY GATE

Before declaring frontend work complete:

1. Inspect the entire page.
2. Check mobile.
3. Check tablet.
4. Check desktop.
5. Check keyboard navigation.
6. Check focus states.
7. Check contrast.
8. Check overflow.
9. Check loading states.
10. Check empty states.
11. Check error states.
12. Check console errors.
13. Check performance.
14. Check visual consistency.

If any major issue exists, fix it before reporting completion.

Do not say "done" merely because the application compiles.
